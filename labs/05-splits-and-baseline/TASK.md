# Task

**1. Predict, in writing, first.**

Open `experiments/05-split-comparison.md` and write, before running anything:

- what a random row-wise split measures;
- what a split that holds out whole projects measures;
- which number you expect to be higher, and by how much;
- what result would tell you your reasoning was wrong.

Do not edit this file after you see the result. Append to it.

**2. Ask the deployment question.** In `decisions/05-split-choice.md`: when this system runs
in production, is it seeing tests from projects it has trained on, or projects it has never
seen? Your split must match that answer. Write the answer *before* you look at which split
gives a nicer number.

**3. Build it.** `ci_triage/splits.py` — a grouped splitter. sklearn has this; use it, and
write only the wiring.

**4. The invariant test.** `tests/test_splits.py` must fail if any project appears on both
sides of any fold. This is a bug that is invisible in the metrics and fatal to the claim.

**5. Run both.** Same model, same features, both splits. Report mean and standard deviation
across folds. Write both to `artifacts/results/baseline.json`, along with the majority
baseline on the real data.

**6. Defend it.** The coach will attack one of your numbers. Your defence goes in
`.ci-lab/interviews/05.md` if you want it kept, though the gate for this phase does not
require it — phase 06's does.
